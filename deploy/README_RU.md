# SaqQo: сайт и API на одном HTTPS-домене

Подготовлен вариант размещения: https://render.com/deploy?repo=https://github.com/donix873/SAQQO
Нужен вход владельца в Render. Вписать три серверных ключа в защищённые переменные, затем дождаться сборки. Сайт откроется по адресу `<адрес-сервиса>/SAQQO/`. Отдельный API URL в клиенте не нужен. Ключи в браузер не передаются.

В этой среде нет сессии Render, поэтому данный Docker/Render-вариант пока не развёрнут и не проверен на хостинге. Бесплатный план предназначен для демонстрации: сервис засыпает, SQLite может исчезнуть после перезапуска контейнера. Для постоянной модерации нужно постоянное хранилище. Публичный QR презентации ведёт на GitHub Pages; менять его на Render следует только после успешной проверки нового адреса.

Для выступления с ноутбука проверенный локальный вариант:

```
python -m venv .venv
.venv/bin/pip install -r server/requirements.txt
.venv/bin/python tool/run_presentation.py --secrets /путь/к/yandex.json --web-dir build/web
```

На Windows запускать `.venv\Scripts\python` и `.venv\Scripts\pip`. Формат JSON — имена `YANDEX_GEOCODER_API_KEY`, `YANDEX_ROUTE_DETAILS_API_KEY`, `YANDEX_DISTANCE_MATRIX_API_KEY` со значениями. Файл ключей держать за пределами build/web и Git. Открыть http://127.0.0.1:8765/SAQQO/ после запуска. Это локальный адрес ноутбука, для аудитории используется опубликованный HTTPS-сайт.

Публикация статической сборки: сначала обновить ветку gh-pages тестированной сборкой с base-href /SAQQO/, затем отправить изменения main. Workflow main публикует эту сборку. Изменения Dart сами по себе не пересобирают gh-pages.
