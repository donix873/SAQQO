# SAQGO — с чего начать

В проекте есть редактируемая визуальная концепция и исходники Flutter MVP. После запуска на телефоне навигация, выбор языка, карта, запрос GPS, добровольная сенсорная сессия, локальная история и переход к системному набору 112 работают как приложение. Внешние данные риска, безопасная маршрутизация, сервер и BLE не считаются готовыми без отдельной инфраструктуры и проверок.

## 1. Посмотреть дизайн

Самый простой путь в этом рабочем пространстве:

1. Откройте файл `SAQQO/design/gallery.html`.
2. Вверху переключайте язык: **Русский** / **Қазақша**.
3. Рядом переключайте устройство: **iOS** / **Android**.
4. Клик по картинке открывает PNG крупнее; ссылка `Исходник SVG` под ней — редактируемый векторный исходник.

В галерее лежат пять главных экранов:

| Файл | Что это |
| --- | --- |
| S03 | главная карта |
| S08 | поиск и выбор маршрута |
| S06 | добровольная запись SmartRoads |
| S11 | история поездок LifeLog |
| S13 | экстренный экран SOS / звонок 112 |

Каждый экран существует в четырёх вариантах: RU-iOS, RU-Android, ҚАЗ-iOS, ҚАЗ-Android. Всего 20 макетов. Обзор русской iOS-версии: `design/overview.png`.

Если проект открыт у вас на компьютере, можно открыть галерею двойным кликом. Если браузер не показывает локальные картинки, в терминале выполните:

```sh
cd /workspace/SAQQO
python -m http.server 8080 --bind 127.0.0.1
```

Затем перейдите в браузере на `http://127.0.0.1:8080/design/gallery.html`. Остановить сервер: `Ctrl+C` в этом же терминале.

## 2. Что смотреть при проверке дизайна

Проверяйте каждый из пяти экранов в обеих локалях и на обоих устройствах:

- текст легко читается и не обрезается;
- казахские буквы отображаются правильно: Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І;
- на экране нет выдуманных улиц, рисков или сообщений, похожих на реальные;
- на карте и показателях видна пометка «Демо»;
- SOS предлагает открыть системный звонок 112, но не утверждает, что помощь уже вызвана;
- SmartRoads не обещает определить лёд, люки или настоящую яму;
- все нужные действия понятны: маршрут, запись, история, SOS.

Запишите решение по каждому экрану так: `S03 — принять` или `S03 — изменить: …`. Лучше указывать элемент и вариант: например, `S08 / ҚАЗ / Android — увеличить подпись второго маршрута`.

## 3. Как менять дизайн

Есть два безопасных способа.

### Нужна только правка или комментарий

Не меняйте файлы в `design/exports/`: это готовые экспортированные изображения. Запишите правки отдельным списком и передайте его разработчику. Так изменения не потеряются при следующем экспорте.

### Нужна самостоятельная правка исходника

1. Откройте нужный файл из `design/exports/` в Figma, Penpot, Inkscape или другом редакторе SVG.
2. Сохраните результат отдельным вариантом, например `S03_ru_ios_v2.svg`.
3. Не заменяйте файл без резервной копии: команда генерации перезаписывает стандартные файлы.
4. Для финальной версии изменения нужно перенести в `design/generate.py`, иначе при повторной генерации они пропадут.

Тексты RU и ҚАЗ находятся в начале `design/generate.py` в блоке `COPY`. Иконки находятся в `assets/icons/`, а их реестр — в `assets/assets_manifest.csv`.

## 4. Как пересобрать все макеты

В текущей облачной среде зависимости уже установлены. После изменения `design/generate.py` выполните из папки проекта:

```sh
XDG_CACHE_HOME=/workspace/.cache /workspace/.saqgo-design-venv/bin/python design/generate.py
/workspace/.saqgo-design-venv/bin/python design/validate.py
```

Вторая команда обязательна: она проверяет 20 экспортов, наличие отдельных иконок, прозрачность PNG, размер экранов и выход текста за границы. Успешный результат сейчас: `188 passed, 0 failed`.

На новом Mac/Linux-компьютере сначала создайте виртуальное окружение и установите пакеты:

```sh
python -m venv .venv
.venv/bin/pip install -r design/requirements.txt
.venv/bin/python design/generate.py
.venv/bin/python design/validate.py
```

Для Windows команды запускаются из PowerShell так: `.venv\\Scripts\\python.exe design\\generate.py`.

## 5. Как запустить приложение

1. Установите Flutter stable и Android Studio. Для iPhone также нужен Mac с Xcode и Apple Developer account.
2. Склонируйте репозиторий, откройте терминал в папке `SAQQO` и укажите расположение Flutter:

```sh
export FLUTTER_ROOT=/путь/к/flutter
bash tool/bootstrap_flutter.sh
```

3. Подключите Android-телефон с USB debugging или запустите эмулятор. На iPhone откройте `ios/Runner.xcworkspace` в Xcode и выберите signing team.
4. Проверьте устройство и запустите:

```sh
flutter devices
flutter run
```

При первом запуске выберите язык, пройдите onboarding и откройте карту. Разрешение на геолокацию запрашивается только после нажатия кнопки центрирования. Запись датчиков запускается отдельно на экране SmartRoads. SOS открывает приложение звонков с номером 112; сам факт успешного звонка SAQGO не может проверить.

## 6. Дальнейшая работа: правильный порядок

Не начинайте AI, Bluetooth и backend до утверждения дизайна. Следуйте этому порядку:

1. Утвердить или исправить пять текущих эталонных экранов.
2. Сделать остальные экраны S01–S15 и состояния loading, empty, error, offline, permission denied. Получится минимум 60 основных экспортов: 15 экранов × 2 языка × 2 платформы.
3. Выбрать лицензированного поставщика карты, проверить покрытие именно Аркалыка и заменить схематическую демо-карту. Реальные риски и адреса не добавлять без источника.
4. Создать Flutter-проект и перенести дизайн в настоящие виджеты. Все надписи должны быть текстовыми виджетами, а не текстом внутри картинки.
5. Подключить русскую и казахскую локализацию через ARB-файлы, затем проверить смену языка без перезапуска.
6. Реализовать UI-навигацию, локальную историю и честный SOS → системный набор `112`.
7. Только после этого: разрешения, GPS, сенсорная сессия SmartRoads, карта/поиск/маршруты, сервер и модерация. BLE остаётся исследовательской функцией, не заменой экстренной связи.
8. Проверить приложение на настоящем iPhone и Android: маленький экран, большой шрифт, без интернета, отказ GPS, VoiceOver/TalkBack, RU и ҚАЗ.

## 7. Что нужно решить до реальной разработки

Нужны ответы владельца продукта:

- какой провайдер карт и маршрутов использовать, какой бюджет и ключ доступа предусмотрены;
- какие реальные источники рисков разрешены и кто их проверяет;
- нужен ли backend для первой версии или достаточно локального демо;
- минимальные версии iOS и Android, доступные устройства и Apple Developer account;
- кто проверит казахские переводы и юридические тексты.

Подробные технические ограничения и список того, что ещё не сделано: `design/REVIEW.md`. Полная структура файлов — в `README.md`.
